Modelización de aplicaciones web
Se entiende por capa cada elemento que procesa o trata información. En un modelo de n-capas la información atraviesa varias capas entre la interfaz y la administración de los datos. El más habitual es el modelo de tres capas. Three-tier architecture


Modelo de dos capas
    • Gran parte de la aplicación corre en el lado del cliente (cliente pesado)
    • La lógica de negocio se encuentra en el lado del cliente
    • Inconvenientes
        ◦ Dificilmente escalable
        ◦ Numero reducido de conexiones
        ◦ Carga de red

Modelo de tres capas
    • Diseñada para superar limitaciones del modelo de dos capas.
    • Una capa intermedia contiene la lógica de negocio.
    • Las aplicaciones web actuales se ajustan a este modelo.
Detalle modelo de tres capas
    • Capas de presentación (parte en el cliente y parte en el servidor) 
        ◦ Recoge la información del usuario y lo envía al servidor para que la capa negocio la procese
        ◦ Procesa determinada información
        ◦ Recibe resultados de la capa proceso
        ◦ Generan la presentación y la muestra (HTML, CSS, JS)
    • Capas de aplicación proceso o negocio. Nivel lógico intermedio
    • Capa de datos (servidor/es de bases de datos)

Ambito (scope) de las variables
Con “var” defino la variable global y local en JS
Si se declara una variable en cualquier parte del programa sin usar var automáticamente se convierte en una variable global. (no es muy recomendado)
A partir de la versión ES6 (EcmaScript2015), podemos utilizar “let” para declarar variable.

Coerción
Es la conversión automatica o implícita de valores de un tipo de dato a otro. Es una característica que fuerza a una variable de cierto tipo a tener el comportamiento de una diferente.
La coerción es implícita mientras que la conversión puede ser implícita o explícita.

Una función es un grupo de sentencias o instrucciones que realizan una tarea o calculan un valor.
Para poder utilizar una función hay que definirla en algún lugar del programa y después llamarla (invocarla) ya sea desde dentro del código, en un evento o automáticamente. Devuelve algo si se utiliza un return. 
La estructura más habitual es la denominada por declaración

Function <nombre de la función> (<parámetros opcionales separados por comas>){
	<instrucciones>
}
Pueden invocarse, incluso antes de su definición

    • Introducción
Las funciones pueden o no tener un valor de retorno. Si no se especifica un return, la función devuelve undefined por defecto. Las funciones solo retornan un valor. Si queremos retornar más de uno los podemos agrupar en arrays u objetos
Al usar paréntesis (), se invoca a la función. Sin paréntesis, se referencia al objeto que representa la función
Como las funciones son objetos de primera clase pueden ser asignadas a variables, pasadas como argumentos y devueltas por otras funciones

Saltos. Break y continue
Permiten alterar el flujo del programa, saltando a otro punto del código. Se desaconseja su uso, aunque en switch es prácticamente imprescindible break.
Break termina el bucle y transfiere el control del programa a la siguiente instrucción que se encuentra después de la instrucción de terminación del elemento.
Continue termina la ejecución de las sentencias de la iteración actual del bucle o la etiqueta y continua la ejecución del bucle en la siguiente iteración.
Permite saltar una o más iteraciones
La sintaxis de este tipo de estructuras es la siguiente:
	Break [etiqueta];
	Continue [etiqueta];
Las etiquetas son identificadores opcionales que periten al programa salir de una sentencia que esta etiquetada y que no tiene que ser una sentencia de bucle necesariamente.

Conceptos
En general, se pueden definir como comportamientos anómalos, imprevistos o no. Una aplicación debe disponer de tolerancia a fallos, es decir, de la capacidad de recuperación ante la aparición de errores.
Los errores no se pueden evitar, pero una eficiente gestión de los mismos es fundamental
CUadno se producen
    • Durante el desarrollo

Tipos
Error (no controlado): provoca que la aplicación deje de funcionar
Excepción (controlada): situación en alguna medida esperada que se trata convenientemente
Advertencia(warning): nos avisa de situaciones que pueden evolucionar en un error.

Try-catch
Si sucede un error en el código el programa dejara de ejecutarse, pero el usuario solo advertirá que el programa no hace nada y solo si abre la consola vera el error. En JS (como en muchos otros lenguajes) existe la gestión  de excepciones como:
Try{
…
}catch (error){
…
}

Dentro del bloque try se pone el código a proteger y cualquier error producido en el que será pasado al bloque catch donde es tratado. Opcionalmente puede haber al final de un bloque finally que se ejecuta siempre
